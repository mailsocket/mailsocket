How a signup test uses it

  1. 1

    Create an inbox

    One POST returns an inbox id and a random address on {{ mail_domain }} (why this domain). {% if free_tier %}The free plan includes {{ free_tier.inboxes_display }}; the first is created for you when you verify your email, and you can{% else %}You can{% endif %} reuse it on every run: a wait only matches mail received after its since point (step 3), so an earlier run's code is not returned. Paid plans hold more inboxes, so parallel runs can each get their own.

    POST /api/v1/inboxes → "address": "eqxwebxjzv8kfrvo@{{ mail_domain }}"
  2. 2

    Type the address into the form you are testing

    Your test fills in the email field and submits, the way a user would. Your app sends its normal verification email and needs no changes; mailsocket accepts it and pulls out the code and the link as it arrives.

    page.fill("#email", inbox["address"]) page.click("text=Create account")
  3. 3

    Call wait() for the code

    The request stays open for up to 25 seconds. It answers 200 with the message (the JSON above) the moment a code is found, or 204 when time runs out, and you call it again. By default only mail that arrives after the call starts matches; pass since with a timestamp from just before the submit so a fast email is not missed. For a magic link, use require=link.

    GET /api/v1/inboxes/{id}/messages/wait?require=otp → 200 {"data": {"otp": "482193", …}}

The same flow with the Python SDK

The sample reuses your existing inbox; create_inbox() makes a new one when your plan has room. wait_for_otp() re-issues the 25-second long-poll for you until a code arrives or its own timeout (60 seconds by default) runs out, then returns a WaitResult.

The sample passes since with the time just before the submit, so a code that arrives before the wait starts is still matched and an older code in the reused inbox is not. result.confidence is the message's otp_confidence; to skip bare numbers, add min_confidence=0.9.

For a magic link, call wait_for_link() and read result.magic_link.

signup_test.py
{# Keep sample code plain text (no Cloudflare Email Obfuscation). Runs as written against sdks/python inside a Playwright test (page = the step-2 page). #} 
import time
from mailsocket import Client

client = Client("ms_live_...")    # your API key
inbox = client.list_inboxes()[0]  # or create_inbox()

started = time.time()
page.fill("#email", inbox["address"])
page.click("text=Create account")

result = client.wait_for_otp(inbox["id"], since=started)
print(result.otp)         # 482193
print(result.confidence)  # 0.95

What it does, and what it doesn't

What it does

  • Receives email at addresses on {{ mail_domain }}, or on your own domain on the Scale and Business plans.
  • Extracts the one-time code and the magic link from each message.
  • Returns them as JSON through the wait endpoint, the REST API, a Server-Sent Events stream, or signed webhooks (paid plans).
  • Gives you the full text and HTML body too, when you need more than the code.

What it does not do

  • Send email. The service only receives.
  • Receive SMS or phone-number codes.
  • Open or click magic links. It extracts them; your code decides what to do.
  • Replace a personal mailbox. There is no IMAP or POP access.
